# Video Editing & Rendering Engine

This document details the video compositing pipeline, spatial transitions, speed-ramping curves, color grading, and audio ducking implemented inside `editor_service.py` and `spatial_transitions.py`.

---

## 1. Video Processing Pipeline (`render_clip`)

Each video clip mapped in the EDL is compiled into a processed output segment using the following sequential steps:

```
[User Raw Video]
       |
       v  (Trim & Seek)
[trim=start:end]
       v  (Reset presentation timestamps)
[setpts=PTS-STARTPTS]
       v  (Early CFR conversion - 30 fps)
[fps=fps=30] 
       |
  +----+----+  (Conditional Branching)
  |         |
  | [Custom Speed Ramping]                   | [Constant Speed]
  | setpts='(if(lt(T,t1),...))/TB'           | setpts='(T/speed)/TB'
  | atempo=1.0 / speed                       | atempo=speed
  |         |                                |         |
  +----+----+                                +----+----+
       |
       v  (Scaling & Centered Cropping)
[scale=w:h, crop=1080:1920:x:y]
       v  (Exposure & Tone Grade adjustments)
[eq=contrast:brightness, colorbalance=rm:bm]
       v  (Optical Zoom / Keyframe Ken Burns)
[zoompan=z='1.1-0.04*on/30']
       v  (Text Subtitle & Effect Blends)
[overlay=x:y:shortest=1]
       v  (Audio sample rate normalization)
[aformat=sample_rates=44100:channel_layouts=stereo]
       |
       v
[Processed Output Clip (30fps, 44100Hz Stereo)]
```

### 1.1 VFR & High-Framerate (120 fps) Glitch Resolution
- **Problem**: Raw footage from mobile devices utilizes Variable Framerate (VFR) or high-speed capture (120/240 fps). Applying filters and speed-scaling before framerate normalization caused timestamp desynchronization, resulting in blocky glitches or green frames.
- **Solution**: The `fps=fps=30` filter is prepended to the very beginning of the filter chain (immediately after `setpts=PTS-STARTPTS`). This immediately snaps VFR frames to a constant 30 fps grid, ensuring downstream overlays, speed calculations, and cuts run smoothly.

### 1.2 Pre-Stabilization
If stabilization is enabled:
1. **Pass 1 (Analysis)**: Runs `vidstabdetect` to output motion vectors. The input is resampled to `fps=30` to ensure vector coordinate indexes align with the target video track:
   `ffmpeg -i input.mp4 -vf fps=fps=30,vidstabdetect=... -f null -`
2. **Pass 2 (Transform)**: Stabilizes the video using `vidstabtransform` and outputs to a temporary CFR video:
   `ffmpeg -i input.mp4 -vf fps=fps=30,vidstabtransform=... -ar 44100 -ac 2 temp_stabilized.mp4`
3. **Execution**: The stabilized temporary video is passed to `render_clip` as the source input.

## 2. Speed Ramping Mathematics

Shortify AI supports complex cinematic speed-ramping curves. The Groq Creative Director selects preset pacing:
- **`speed-ramp`**: High speed at start, slowing down near the focal action point, and speeding up again.
- **`cinematic-slow`**: Sustained slow-motion (`speed = 0.75`).
- **`fast-cut`**: Snappy high-speed action (`speed = 1.25`).

### 2.1 Speed Equation Formulation
For speed ramping, time-varying speeds are mapped to frame presentation timestamps ($T$) inside the `setpts` expression:
$$\text{setpts} = \frac{f(T)}{\text{TB}}$$
Where $f(T)$ computes the integrated output timestamp for the input frame at time $T$. The corresponding audio tracks are scaled proportionally using `atempo` (clamped between `0.5` and `2.0`).

## 3. Spatial Transitions (`spatial_transitions.py`)

If a spatial transition (e.g. `slide_right`, `slide_down`, `glitch`, `wipe`) is planned between Clip A and Clip B:

```
                  +--------------------------------+
                  |  Create Spatial Transition     |
                  +---------------+----------------+
                                  |
            +---------------------+---------------------+
            v                                           v
    [ Trim Clip A End ]                         [ Trim Clip B Start ]
  -ss (dur_a - fade_dur)                        -t (fade_dur)
  -vn -c:a aac -ar 44100                      -vn -c:a aac -ar 44100
            |                                           |
            v                                           v
      [ temp_audio_a ]                            [ temp_audio_b ]
            |                                           |
            +---------------------+---------------------+
                                  |
                                  v
                    [ FFmpeg: acrossfade=d=fade ]
                                  |
                                  v
                         [ temp_audio_cross ]
                                  |
         +------------------------+------------------------+
         | (Merge with spatial transition frames generated by OpenCV)
         v
    [ FFmpeg: combine silent transition video & crossfaded audio ]
    -c:v libx264 -pix_fmt yuv420p -c:a aac -ar 44100 -ac 2 -r 30
```

### 3.1 OpenCV Slide Down Fix
In `slide_frames`, sliding matrices are computed frame-by-frame. The slicing indexing for `slide_down` has been corrected to prevent broadcasting errors on 3D color channels:
```python
# Correct slice operation: includes the third dimension (channel layout)
out[shift:, :] = frame_a[:h - shift, :]
```

## 4. Audio Normalization & Ducking

### 4.1 Sample Rate Sync
If audio sample rates mismatch across clips, FFmpeg's `concat` and `acrossfade` filters fail or output corrupted audio. To resolve this, Shortify AI enforces a strict sample format conversion prior to any concatenation or crossfading:
- **`aformat` filter**: `aformat=sample_rates=44100:channel_layouts=stereo` is applied to all audio inputs.
- **Output arguments**: `-ar 44100 -ac 2` are declared on all final render, padding, and transition compilation boundaries.

### 4.2 Intelligent Audio Ducking (`amix`)
When background music is overlaid:
1. Calculates intervals where clips contain spoken audio (`clip_has_audio=True`).
2. Constructs a dynamic volume envelope expression:
   `volume_expr = "if(between(t, start, end), 0.15, 0.40)"`
3. Applies the expression using the `volume` filter to duck background music during spoken voice sections, fading out the music smoothly by `1.5` seconds at the video end using `afade`.

## 5. Visual Overlays & Stickers

- **Loop Overlays**: Uses `-stream_loop -1 -i` for visual overlay inputs (e.g. dust, particles). This loops overlays at the demuxer level, which is highly efficient and prevents FFmpeg from hanging.
- **Sticker Overlays**: Pulls stickers from Giphy (or local assets) and places them in designated target screen coordinates (`top-left`, `bottom-center`, etc.) using the FFmpeg `overlay` filter with dynamic scale mappings.
